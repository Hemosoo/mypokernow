# PokerNow Customizer — Roadmap

## V1 — Animation foundation

Eight distinct reference animations, shared deterministic engine, full-page studio, event-specific assignments, foundational card/table/board styling, portable local themes, DOM-only adapter, robust restoration, tests, and honest compatibility evidence. The deprecated Chain Reaction / One-by-One flop is excluded.

V1 establishes plugin-like registration and reusable source artwork, motion, composition, fragment, and lifecycle primitives. It does not include a full animation editor or arbitrary imported executable code.

## V2 — Advanced visual customization

- Complete 52-card artwork replacement with validated local asset packages.
- Custom chips and dealer buttons.
- Player nameplate styling and more table themes.
- Animated table backgrounds and comprehensive board styling.
- Better native-artwork fidelity and adapter capabilities based on verified site behavior.

Maintain explicit ownership/restoration for every added live visual override. Do not expand permissions simply to bypass an unsupported rendering path.

## V3 — Visual animation creator

- Visual timeline and keyframe editing.
- Motion-path tools, layered compositions, and drag-and-drop visual objects.
- Shared groups, timing relationships, reusable templates, and fragment design tools.
- Live preview using the same production timeline and geometry contract.

Introduce a versioned declarative format containing metadata, event support, typed bounded parameters, visual object references, primitive tracks, curves, keyframes, and groups. Compile validated data into the existing lifecycle contract. Set explicit complexity and duration budgets. Do not permit JavaScript, DOM selectors, dynamic imports, or network hooks in downloaded animation definitions.

## V4 — Community ecosystem

- Shareable theme and animation packs.
- Safe importable declarative presets and a community browser.
- Package manifests, asset licensing, attribution, and compatibility metadata.
- Open-source contribution templates, authoring examples, and regression fixtures.

Community packages remain data and assets. Signing, moderation, and distribution choices must not substitute for runtime validation or compromise MV3 restrictions.

## V5 — Expanded presentation

- Chip movement and pot collection.
- Winning-hand and player-action effects.
- Optional sound packs with accessibility controls.
- Richer effect layers and advanced visual flourishes.

Every addition still consumes legitimately observable information and preserves gameplay usability. New event types require verified adapters, deduplication, bounded lifecycle behavior, reduced motion, and fail-open fallback.

## Architectural continuity

Retain a small adapter boundary, data-only theme schema, independently testable registry, deterministic clock, reusable artwork, exact measured targets, and native restoration leases. These foundations allow unusual community compositions without turning built-in effects into a rigid single visual style.
